# Known gaps (as of this build)

**Security/accounts:** email verification, password reset, per-IP/per-email rate limiting, account export and deletion are implemented and tested. Remaining: no 2FA; no CAPTCHA; IP limits trust `x-forwarded-for` (deploy behind a proxy that overwrites it); session cookie is `secure` only when `NODE_ENV=production`; verification/reset/alert emails are only *delivered* once a real `EmailTransport` is configured (console/file only today).
**Data:** the `pg` adapter (`DATABASE_URL`) passes the full unit suite (59 tests) and browser suite (18 tests) on a local PostgreSQL 16.15, as well as on PGlite. Not tried on a managed provider: TLS/`sslmode`, PgBouncer transaction pooling vs `SET LOCAL ROLE`/advisory locks, connection limits. RLS covers `profiles` and `saved_searches` only and is bypassed by a superuser connection outside `withUser()`.
**Scheduling:** `/api/cron/{ingest|alerts|outbox|cleanup}` (Bearer `CRON_SECRET`, >=16 chars, disabled if unset) is implemented; nothing *calls* it until you configure a scheduler (Vercel Cron, GitHub Actions schedule, cron-job.org, ...). `npm run ingest|alerts` do the same from a shell.
**Admin source creation:** validated (https only, per-adapter strict config, mandatory permission URL, created disabled). Literal private/loopback/metadata IPs are blocked at creation *and* fetch time, but hostnames that *resolve* to private IPs are not checked — add egress rules. Covered by unit tests; the admin form itself has no browser test because e2e has no admin bootstrap.
**AI:** off unless `AI_PROVIDER` is set; UI is opt-in per click (suggest -> user accepts). Browser-tested with the mock provider only; the Anthropic call was never made live.
**Product:** CV PDF can't render Arabic (printable view works); landing-page names aren't translated; no employer applicant tracking; no admin UI to edit/delete sources.
**Dependencies:** Next 16.4.2 (clears the `next`/`postcss` advisories). `npm audit` still reports 5 high findings in the dev-only lint chain (`eslint-config-next` -> `@next/eslint-plugin-next` -> `fast-glob` -> `micromatch` -> `braces <=3.0.3`; stack exhaustion on deeply nested glob patterns). No patched `braces` existed when checked (latest 3.0.3); `npm audit fix --force` would *downgrade* to Next 14 — don't run it. Not reachable from user input at runtime.
**Ops:** domain today-jobs.com not purchased (placeholder via `SITE_URL`); CI runs on GitHub Actions and passes (typecheck, lint, unit tests on real Postgres 16 and on PGlite, build, 18 browser tests; run 38953120718 on commit 46e7dab) — GitHub only warns that the v4 actions run on a newer Node; Greenhouse / Anthropic / AdSense integrations have never been exercised live (see integrations-registry.md).
